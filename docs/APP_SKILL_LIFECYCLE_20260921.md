# AppSkill 실행·재사용·복구 검증 — 2026-09-21

현재 개발 APK의 기본 계획 모델은 `gpt-5.6-luna`다. 새 요청은 관찰한 화면과 설치 앱 목록으로 계획하고, 재사용 가능한 요청은 로컬 AppSkill을 먼저 실행한다. 경로가 맞지 않으면 현재 화면에서 AI로 복구하며, 실제 완료 조건을 검증한 뒤 같은 스킬을 갱신한다.

## 이번 변경

- 결과 문장의 고정 부분은 해시·길이, 변하는 입력값은 parameter 위치로 저장한다. `저장된 기록: ...`, `검색 결과: ...`를 새 입력값으로 검증하면서 원문·입력값·결과 본문은 저장하지 않는다. 단어·숫자의 일부만 일치하는 값은 일반화하지 않는다.
- `라고/이라고`, `로/으로` 경계가 바뀌면 조사를 입력값에 붙여 추측하지 않고 AI에 넘긴다. 검증된 표현은 다음 요청에서 재사용한다.
- 실행에 쓰이지 않은 넓은 parser 인자에 페이지 이름과 실제 입력값이 함께 들어 있으면, 관찰된 입력값을 parameter로 남기고 페이지 이름은 요청의 고정 부분으로 검증한다. 실제로 여러 단계에 사용한 겹치는 입력값은 유지한다.
- 복구 시 다른 시작 앱에서 실제로 관찰한 앱 진입과 후속 경로도 갱신한다. 길이가 다른 요청으로 복구해도 원래 요청의 입력 구간을 덮어쓰지 않는다. 화면에 맞지 않는 모델의 재사용 제안은 기존 정상 스킬을 실패 상태로 바꾸지 않는다.
- 스크롤 방향과 verifier가 선택한 영역을 저장·복원한다. 상·하·좌·우 모두 같은 방향의 영역이 여러 개여도 지정한 대상을 다시 검증한다.
- 짧은 WebView 내용이 화면 가장자리에 있다는 이유로 이미지 분석을 요구하지 않는다. WebView의 실제 자식 내용과 외부 도구 모음을 구분한다. 현재 노드의 모든 완료 조건으로 충분히 검증되면 과거 보조 스크린샷을 요구하지 않는다. 좌표 동작과 시각 정보만 있는 완료는 계속 이미지 검증이 필요하다.
- 잘못된 선택적 `skill_reuse` 인자는 버리고 유효한 다음 동작을 검증한다. 실제 동작·완료 정보의 파싱 및 verifier 검사는 유지한다. 모델 오류는 원문 응답·키를 노출하지 않는 진단과 종료 이벤트로 기록한다.

새 의존성은 추가하지 않았다. 기존 화면 관찰 → grounding → `VerifiedPlan` → 실행 직전 재검증 → 실행 결과·최종 목표 검증 구조를 사용한다.

## 적용과 검증 범위

최종 로컬 APK와 삼성 기기에 설치한 `base.apk`의 SHA-256이 일치한다.

```text
8f420aefeb71da7cc4e3281eb302a79207239e3c6957512d33623f403594fe6e
```

확인한 것은 이 문서의 명령과 회귀 검사 범위다. 모든 앱·사이트·명령의 무오류, 음성 인식률, 인증·결제 전체 흐름, 다른 제조사/OS 및 공개 출시 준비까지 검증한 것은 아니다. 새로운 의미·동적 결과·불명확한 입력 경계에는 AI 호출이 필요할 수 있다. 최단화는 실제 관찰해 검증한 경로 안에서 수행한다. Android 보안 화면과 사용자 인증 경계는 기존 [실행·안전 계약](SAFETY_CONTRACT.md)을 유지한다.
