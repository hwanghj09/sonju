# Sonju 완료 검증과 Fast Path 개선 기록

2026-09-12. Samsung SM-F731N 실기와 Android 에뮬레이터에서 검증했다. 아래 실기 명령은 음성 인식 결과에 해당하는 문장을 실제 Sonju 실행 경로에 전달한 시험이다. 실제 마이크로 말한 발화의 인식률을 측정한 결과는 아니다.

## 변경한 동작

- 성공한 요청의 경로와 최종 결과 근거를 함께 저장한다. 시작 앱이 다르거나 존댓말·띄어쓰기가 조금 달라도 같은 요청을 찾는다. 입력값과 숫자 결과는 구분하며, 기존 경로와 달라지면 현재 관찰부터 복구한다.
- 마지막 화면의 제목·결과·체크 상태를 새로 관찰해 검증한다. 앱 실행, 화면 전환, 모델의 완료 선언만으로 전체 요청을 성공 처리하지 않는다. 저장하는 결과는 원문 대신 해시이며, 재실행 시 현재 화면의 실제 값을 사용한다.
- 화면 전환 애니메이션으로 버튼이나 입력란이 이동하면 내용과 대상의 동일성을 검증해 다시 연결한다. 라벨 없는 스위치는 고유한 리소스 ID와 전체 화면 내용·체크 상태가 유지되어야 한다. 실제 클릭 직전에도 체크 상태를 다시 확인한다. 다른 버튼, 바뀐 금액, 다른 입력값에는 이 예외를 적용하지 않는다.
- 깊은 UI 트리의 긴 경로 대신 `node=번호`를 모델에 제공하고, 응답을 해당 관찰의 실제 노드 경로에 연결한다. 숨겨진 노드, 민감 노드, 범위 밖 번호는 연결하지 않는다. 실행 시에는 다시 현재 노드를 검증한다.
- 인식된 확인 응답을 한 번만 소비한다. 이전 녹음의 늦은 응답과 중간 인식 결과는 승인할 수 없다. 안내 음성이 끝난 뒤 답변을 받고, 거절·시간 초과는 실행하지 않는다. 실행 중 중단과 완료 안내 후 다음 음성 요청도 처리한다.
- 시간과 이름이 명확한 타이머 시작은 기기에서 해석해 Android 표준 타이머 기능을 호출한다. 요청과 매개변수를 검증하고, 이름·일시정지 버튼·서로 다른 두 시점의 감소하는 남은 시간을 확인한다. 결과를 읽지 못했을 때 타이머 생성을 자동으로 반복하지 않는다.
- 길찾기에서 앱 이름, 출발지, 목적지를 분리한다. 사용자가 지정한 앱의 별칭을 설치 목록으로 확인한 뒤 사용한다.

타이머의 플랫폼 계약: [Android AlarmClock.ACTION_SET_TIMER](https://developer.android.com/reference/android/provider/AlarmClock#ACTION_SET_TIMER). 현재 기기 내 문법은 숫자로 인식된 시간·분·초, 1초부터 24시간까지의 명확한 시작 요청을 처리한다. 다른 표현은 기존 계획 경로를 사용한다.

## 실기 결과

각 실행의 문장, 시간, 도구 수, AI 호출 수, 최종 화면은 `app/build/reports/completion-qa/<실행 이름>/`의 `result.json`, `flow.log`, `screen.xml`에 기록한다. 동일 결과 화면에서 재조회한 경우와 실제 경로를 다시 실행한 경우를 구분한다.

| 요청 / 시작 조건 | 결과 | AI 호출 | 기록 |
|---|---|---:|---|
| 설정 앱을 초기 화면으로 되돌린 뒤 글자 크기 및 스타일 메뉴 열기, 존댓말로 반복 | 메뉴 도착, 5.2초 | 0 | `font-switch-final` |
| 굵은 글씨 켜기 → 끄기 반복 | 실제 상태 변경, 3.2초 / 2.7초, 끈 상태로 복원 | 0 / 0 | `bold-on-switch-final-2`, `bold-off-switch-final-2` |
| 입력을 지운 계산기에서 168 곱하기 23 계산 | 3,864, 1.8초, 저장된 입력 경로 2단계 | 0 | `calculator-switch-final` |
| 손주 테스트라는 이름의 10분 타이머 시작 | 이름과 실제 카운트다운 진행 확인, 2.9초 | 0 | `timer-start-switch-final` |
| 실행 중인 손주 테스트 타이머 취소 반복 | 실제 취소 후 시작 화면까지 확인, 2.9초 | 0 | `timer-cancel-switch-final` |
| 구글 지도에서 서울역 → 시청역 대중교통 경로 조회 | 출발지·목적지·대중교통 결과 확인, 43.2초 | 4 | `maps-short-nodes-final` |
| 위 경로 결과가 표시된 상태에서 같은 요청 재조회 | 현재 결과 근거 확인, 1.2초, 추가 조작 없음 | 0 | `maps-replay-final` |

설정 메뉴의 이전 학습 실행은 AI 5회·42.8초였다. 개선 후 설정 초기 화면부터 메뉴까지 반복 경로는 AI 0회다. 타이머의 일반 UI 탐색은 처음에 실행 한도까지 사용하고도 완료를 확인하지 못했으나, 표준 기능 경로에서는 첫 실행부터 AI를 호출하지 않는다.

표현이 달라진 모든 문장을 기존 요청과 자동으로 동일시하지는 않는다. 실제로 ‘메뉴를 열어주세요’를 ‘화면을 열어주세요’로 바꾼 첫 실행은 AI 3회로 완료했고, 같은 새 문장을 설정 초기 화면부터 다시 실행했을 때 AI 0회·5.8초로 통과했다(`font-apk-final`, `font-new-wording-replay`). 첫 기록의 `passed=false`는 화면 도착 실패가 아니라 시험에서 요구한 AI 0회 조건을 만족하지 못했기 때문이다.

## 최종 빌드 검증

- `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest` 통과. 단위 시험 293개 중 289개 통과, 실제 API를 사용하는 선택 시험 4개는 기본 실행에서 제외했다(`unit-tests-switch-final`).
- 제외된 실제 모델 API 시험 4개는 별도 실행에서 모두 통과했다(`live-model-final-build.xml`). 합성 관찰과 이미지 입력에 대한 모델 응답 시험이며 실기 전체 작업 시험과는 구분한다.
- 최종 APK의 Android 시험은 12개 통과, 설치 앱을 실제 모델에 전달하는 선택 시험 1개 제외다(`native-switch-final.txt`). 음성 콜백, 실제 접근성 제스처와 터치 차단, 설치 앱 목록, 사용자 인증 단계 인계, 매니페스트·온보딩을 포함한다.
- Lint 오류 0개, 경고 80개. 릴리스 병합 매니페스트에서 디버그 화면 관찰 수신기가 없음을 확인했다.
- Samsung에 설치한 APK와 `app/build/outputs/apk/debug/app-debug.apk`의 SHA-256이 일치한다: `e29a8d9f6dd87fefa5f328e4d2a96f622e3c835360a32f21ac0734cb58826f60` (`installed-apk-final.json`).

마지막 스위치 보완 후 설정 메뉴·굵은 글씨 켜기/끄기 두 차례·지운 계산기·타이머 시작/취소를 같은 최종 APK로 다시 검사했고 모두 AI 0회였다. 테스트 타이머는 취소했고, 굵은 글씨는 원래의 꺼진 상태로 복원했다. 글자 크기 값은 2로 유지했다. 길찾기 실행과 재조회는 앞선 모델 노드 참조 수정 단계의 기록이다.

## 검증 방법과 한계

기기 명령 재현 도구는 `scripts/verify-device-command.py`이다. `--no-model`은 실행 완료와 실제 결과를 확인하고 AI 호출이 0회일 때만 통과한다. 제한 시간이 지나면 중단 명령을 전달한다. 화면은 `DUMP` 권한으로 보호된 디버그 전용 수신기로 새로 읽으며, 이전 UiAutomator 출력 파일을 재사용하지 않는다. 이 수신기는 릴리스에 포함되지 않는다. 민감 노드는 출력하지 않는다.

음성 콜백 시험은 실제 Android 서비스에서 확인·거절·시간 초과·중복·이전 응답·중단·다음 요청 연결을 검사한다. 이 시험과 Vosk/마이크를 통한 실제 발화 시험은 별개다. 실제 인증·결제·메시지 전송은 실행하지 않았다. 다른 제조사·앱 버전·전체 앱의 임의 요청에 대한 성공률도 이번 결과로 보장하지 않는다.

실패했던 초기 실행도 같은 보고서 폴더에 남겼다. 특히 초기 길찾기는 결과 화면에 도착했어도 완료 근거가 잘못되어 실패했고, 초기 취소는 실제 타이머를 멈춘 뒤에도 완료 판단을 못 했다. 화면 요소 참조와 완료 후 상태 해석을 수정한 뒤 위 명령을 다시 실행해 검증했다.
